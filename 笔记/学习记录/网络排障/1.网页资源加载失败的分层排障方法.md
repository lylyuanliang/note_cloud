# 网页资源加载失败的分层排障方法

这份笔记沉淀一套通用判断方法：当页面主体能打开，但 JS、CSS、图片或字体等子资源失败时，不要只看浏览器最终报错，要把链路拆成 DNS、TCP、TLS、HTTP、CDN 节点和浏览器缓存几个层次逐一判断。

可直接使用的脚本和操作步骤见：[网页资源加载与 CDN 节点排障工具箱](../../教程/浏览器/网页资源加载排障/1.网页资源加载与CDN节点排障工具箱.md)。

## 核心判断路径

推荐顺序：

1. 先确认主页面是否能拿到 HTML。
2. 提取页面引用的全部子资源。
3. 按资源主机聚合，找出资源数量最多或失败最集中的主机。
4. 对每个主机依次验证 DNS、TCP、TLS/HTTPS。
5. 如果主机是 CDN 域名，再逐 IP 判断是否存在部分边缘节点异常。
6. 最后再决定是客户端绕过、代理规则调整、hosts 固定，还是反馈服务方修复。

## 浏览器报错和网络层含义

| 浏览器现象 | 常见含义 | 优先检查 |
| --- | --- | --- |
| `ERR_NAME_NOT_RESOLVED` | 域名没有解析结果 | DNS、hosts、代理 DNS |
| `ERR_CONNECTION_TIMED_OUT` | 连接建立或响应等待超时 | TCP 连通、路由、异常 CDN 节点 |
| `ERR_CONNECTION_RESET` | 连接被对端或中间链路重置 | TLS 配置、边缘节点、防火墙 |
| `ERR_SSL_PROTOCOL_ERROR` | TLS/HTTPS 协议协商失败 | 证书、SNI、服务端 HTTPS 配置 |
| 页面白屏但 HTML 200 | 子资源或前端运行时失败 | Network 资源列表、Console 错误 |

同一个报错不一定只对应一个原因。比如 `ERR_CONNECTION_TIMED_OUT` 可能是主域名不可达，也可能是某个静态资源域名不可达；页面资源很多时，后者更容易被误判。

## 为什么要按资源主机聚合

现代前端页面通常不是只访问一个域名：

- 主站域名返回 HTML。
- 静态资源域名返回 JS、CSS、图片和字体。
- 对象存储或 CDN 域名返回大文件。
- 统计、监控、登录组件还可能访问额外域名。

如果主 HTML 能打开，不能说明整个页面链路正常。真正让页面白屏的，往往是占比最高的一组 JS/CSS 资源所在主机失败。

排查时要先回答两个问题：

- 页面一共引用了哪些资源主机？
- 失败资源是否集中在同一个主机？

这也是 [diagnose_page.py](../../教程/浏览器/网页资源加载排障/scripts/diagnose_page.py) 的主要价值。

## DNS、TCP、TLS、HTTP 的边界

| 层次 | 验证目标 | 成功说明 | 失败说明 |
| --- | --- | --- | --- |
| DNS | 域名能解析到 IP | 名字能找到地址 | DNS、hosts、代理解析异常 |
| TCP | IP 的 80/443 端口能连接 | 网络路由和端口基本可达 | 路由、端口、防火墙或节点不可达 |
| TLS | 能完成 HTTPS 握手 | 证书/SNI/协议基本正常 | 证书、SNI、CDN HTTPS 配置可能异常 |
| HTTP | 能返回状态码和内容 | 应用层可响应 | 路径、鉴权、缓存、服务状态异常 |

关键点：TCP 成功不等于 HTTPS 成功。一个节点可能 443 端口开放，但 TLS 握手失败；这类问题在 CDN 边缘节点证书配置不一致时尤其常见。

## CDN 多节点问题的特征

CDN 域名通常会解析到多个 IP。不同地区、运营商、DNS 缓存和浏览器连接复用可能命中不同节点。

典型特征：

- 同一个页面有时能打开、有时白屏。
- 刷新、清 DNS、重启浏览器后结果变化。
- 代理访问稳定，直连偶发失败。
- 逐 IP 检查时，一部分 IP 返回 `HTTP/1.1 200 OK`，另一部分 IP 超时或连接重置。

这时不要只说“网站坏了”或“本地网络坏了”，应保留异常 IP、失败类型、测试时间和可用 IP，便于服务方定位 CDN 边缘节点。

## 浏览器缓存和连接池的影响

浏览器可能缓存 DNS 结果，也会复用已有 socket 连接。即使系统 DNS 已经刷新，浏览器内部仍可能继续使用旧解析结果或旧连接。

因此客户端侧排除问题时，完整动作通常是：

1. 保存未提交表单。
2. 优雅关闭浏览器。
3. 执行 `ipconfig /flushdns`。
4. 重新打开浏览器并恢复标签页。

对应脚本是：[flush-restart-chrome.cmd](../../教程/浏览器/网页资源加载排障/scripts/flush-restart-chrome.cmd)。

## 排障记录应保留什么

一次有效的网络排障记录至少应包含：

- 目标 URL 和失败资源 URL。
- 失败发生时间和网络环境。
- DNS 解析结果。
- TCP 端口检查结果。
- HTTPS/TLS 错误类型。
- CDN 逐 IP 检查结果。
- 临时绕过方式和验证结果。

不需要长期保留的内容：

- 大量重复的浏览器截图。
- 临时生成的 HTML、日志、缓存文件。
- `.pyc`、`__pycache__` 等运行产物。
