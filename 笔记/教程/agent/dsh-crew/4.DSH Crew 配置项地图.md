# DSH Crew 配置项地图（界面 vs 文件）

更新时间：2026-09-30
适用版本：`@zseven-w/dsh-crew 0.1.0-rc.11` · `codex-cli 0.159.0`

## 这篇解决什么问题

配置 DSH Crew 接入 Codex 时，有一部分设置**在界面里根本找不到**，只能改文件；还有一部分**改完不重启不生效**。这篇把每一项都标清楚：**在哪改、改成什么、什么时候生效、怎么验证**。

## 总表：哪一项有界面、哪一项只能改文件

| 配置项 | 界面 | 文件 | 生效时机 |
|---|---|---|---|
| Hub 地址 | ✅ DSH Crew 设置 → 运行 → Hub 地址 | `~/.config/dsh-crew/config.json` → `hub_url` | 立即（hub 每次请求都读） |
| **档位 → 模型路由**（`flash_provider/flash_model/pro_provider/pro_model`） | ❌ **无界面** | 同上 | **重启 Codex**（MCP 启动时读一次） |
| 默认档位 / 默认推理 / 执行模式 / 默认超时 / 档位策略 / 失败升档 / 两档 Agent 预设 | ✅ DSH Crew 设置 → 派发 / 运行 | 同上 | 重启 Codex |
| 视觉 / 生图 provider | ✅ DSH Crew 设置 → 多模态 | 同上 | 重启 Codex |
| 自定义 provider（给视觉/生图用，**不是** worker 模型） | ✅ 多模态卡片内 | 同上 `custom_providers` | 重启 Codex |
| DSH 的 provider（火山/日日新/cline…） | ✅ DSH 设置 → 模型 | profile 的 `cordis.patch.yml` | DSH 侧热加载 |
| 手写模型的推理档位 | ✅ 装 `dsh-thinking-effort` 后：设置 → 第三方模型思考强度档位 | profile 的 `cordis.patch.yml`（插件自动写） | 即时 |
| **Codex 侧注册 dsh-crew MCP** | ✅ Codex 设置 → MCP → Add server | `~/.codex/config.toml` | **重启 Codex** |
| **hooks（拦截/注入）** | ⚠️ 只能"信任/管理"，**不能新增** | `~/.codex/hooks.json` | 信任后即时；改动条目需**重新信任** |
| 插件自带的角色文件 | ✅ 插件设置页「还原」可删 | `~/.codex/agents/ds-flash.toml`、`ds-pro.toml` | 重启 Codex |
| 全局派发规则 | ❌ | `~/.codex/AGENTS.md` | 新会话生效 |

## 一、`~/.config/dsh-crew/config.json`（插件主配置）

**完整示例（本机验证可用、零额外 API key 版本）**：

```json
{
  "default_tier": "flash",
  "default_effort": "high",
  "mode": "auto",
  "default_timeout_seconds": 1800,
  "hub_url": "http://127.0.0.1:19387",
  "tier_policy": "auto",
  "escalate_on_failure": false,
  "vision_provider": "off",
  "vision_model": "default",
  "imagegen_provider": "off",
  "custom_providers": [],
  "extra_models": {},
  "flash_provider": "huoshan",
  "flash_model": "DeepSeek-V4.1-Flash",
  "pro_provider": "huoshan",
  "pro_model": "DeepSeek-V4.1-Flash",
  "preset_flash": "default",
  "preset_pro": "default"
}
```

逐项说明：

| 字段 | 含义 | 注意 |
|---|---|---|
| `hub_url` | DSH 实例地址 | 出厂默认 `http://127.0.0.1:3080`，桌面版通常不是这个端口 |
| `tier_policy` | `auto` / `flash-only` / `pro-only` | `flash-only` 会把 pro 请求**夹成** flash |
| `default_effort` | `off` / `high` / `max` | 必须是目标模型档位集合里的值 |
| `flash_provider` / `flash_model` | flash 档实际用的路由与模型 | 空 = 回退出厂值 `deepseek-official`（**需要单独 key，本方案不要**） |
| `pro_provider` / `pro_model` | 同上，pro 档 | 同理 |
| `preset_flash` / `preset_pro` | hub 模式下 worker 用的 DSH Agent 预设 | `default` = 跟随 DSH 默认 |

**这项也有"临时改法"**：在 Codex 会话里让模型调 `dsh_worker_config`，传同样的字段。它是 **session-only** 覆盖（不改文件、重启失效），好处是会当场回显 `bindings` / `available_providers`，适合试路由。

> 注意：插件的 `/dsh-config` prompt **不支持**这四个路由字段（它的参数映射表里没有），别指望用它改路由。

## 二、`~/.codex/config.toml`（Codex 侧 MCP 注册）

追加到文件末尾（独立 TOML 表）：

```toml
[mcp_servers.dsh-crew]
command = "node"
args = ["C:\\Users\\<you>\\.dsh\\profiles\\<profile>\\node_modules\\@zseven-w\\dsh-crew\\src\\server.mjs"]
default_tools_approval_mode = "approve"
tool_timeout_sec = 3600
```

要点：

- **反斜杠必须双写**。写成单反斜杠会导致 TOML 解析失败，Codex 会**静默忽略**这段定义（只在日志里留一条 warning）。
- `default_tools_approval_mode = "approve"`：插件文档点名的必需项。
- `command = "node"`：需要 Node 在 PATH；否则写绝对路径。
- 这段与界面「MCP → Add server」等效；界面表单字段是 Name / 类型(stdio) / Command to launch / Arguments / Working directory。

**生效时机**：重启 Codex 桌面版（新会话才会带上工具）。

**验证**：

```powershell
codex mcp list | Select-String dsh-crew
```

### 3.2 必须先"信任"，否则钩子不执行

Codex 对 hook 有信任门禁，界面文案是：

- `Disabled until hook is trusted`（未信任 = 禁用）
- `Hook changed since last trusted`（条目内容变了 = 需要重新信任）

操作：**Codex 设置 → Hooks → 逐条信任**。信任后 Codex 会把哈希写进 `~/.codex/config.toml`：

```toml
[hooks.state.'C:\Users\<you>\.codex\hooks.json:pre_tool_use:0:0']
trusted_hash = "sha256:..."

[hooks.state.'C:\Users\<you>\.codex\hooks.json:user_prompt_submit:0:0']
trusted_hash = "sha256:..."
```

**只要改动了某个 hook 条目（包括 matcher 和命令），就必须重新信任那一条。**

### 3.3 脚本一：`deny-subagent-dispatch.ps1`（PreToolUse 拦截）

```powershell
# PreToolUse hook：阻止 Codex 用自建子代理（spawn_agent）替代 DSH 派发。
#
# 契约（codex 0.159.0 的 pre-tool-use.command.output schema）：
#   - 输入：stdin 一段 JSON，含 hook_event_name / tool_name / tool_input / cwd / session_id ...
#   - 输出：stdout 打印 JSON；不打印 = 放行。
#       拒绝：{"decision":"block","reason":"..."}
#       或：  {"hookSpecificOutput":{"hookEventName":"PreToolUse",
#                                  "permissionDecision":"deny",
#                                  "permissionDecisionReason":"..."}}
#   - 任何解析失败都必须放行（exit 0），不能把正常工具调用卡死。
$Mode = 'strict'   # 'strict' = 禁止一切 spawn_agent；'dispatch-only' = 只在内容像“派给 worker”时才拦

$ErrorActionPreference = 'Stop'
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
try { [Console]::InputEncoding = [System.Text.Encoding]::UTF8 } catch { }

$logDir = Join-Path $PSScriptRoot 'logs'
$logFile = Join-Path $logDir 'deny-subagent-dispatch.log'

function Write-HookLog([string]$Message) {
    try {
        if (-not (Test-Path -LiteralPath $logDir)) {
            New-Item -ItemType Directory -Path $logDir -Force | Out-Null
        }
        Add-Content -LiteralPath $logFile -Encoding UTF8 -Value (('{0} {1}' -f (Get-Date -Format 'yyyy-MM-dd HH:mm:ss'), $Message))
    } catch { }
}

$inputJson = [Console]::In.ReadToEnd()
if ([string]::IsNullOrWhiteSpace($inputJson)) { exit 0 }

try { $event = $inputJson | ConvertFrom-Json } catch { exit 0 }

$toolName = [string]$event.tool_name
Write-HookLog ("INVOKED event=$([string]$event.hook_event_name) tool=$toolName mode=$Mode")
if ($toolName -notmatch 'spawn_agent') { exit 0 }

$payload = ''
try { $payload = ($event.tool_input | ConvertTo-Json -Depth 12 -Compress) } catch { $payload = '' }

$block = $false
if ($Mode -eq 'strict') {
    $block = $true
} else {
    foreach ($keyword in @('worker', 'ds-flash', 'ds-pro', 'dsh', '派给', '派发')) {
        if ($payload -match [regex]::Escape($keyword)) { $block = $true; break }
    }
}

if (-not $block) { exit 0 }

$reason = '已禁用 Codex 自建子代理：请把任务派给 DSH。用 exec 调用 tools.mcp__dsh_crew__dsh_run_worker，参数 { task: <自包含的完整任务，含绝对路径与验收标准>, tier: "flash"|"pro", cwd: <当前工作区绝对路径> }；不要用 spawn_agent 代替 DSH 派发，也不要自己实现被指派出去的任务。'

$preview = $payload
if ($preview.Length -gt 300) { $preview = $preview.Substring(0, 300) }
Write-HookLog ("BLOCK mode=$Mode tool=$toolName input=$preview")

$out = [ordered]@{
    decision           = 'block'
    reason             = $reason
    hookSpecificOutput = [ordered]@{
        hookEventName            = 'PreToolUse'
        permissionDecision       = 'deny'
        permissionDecisionReason = $reason
    }
}

$out | ConvertTo-Json -Depth 5 -Compress
exit 0
```

### 3.4 脚本二：`dsh-dispatch-hint.ps1`（UserPromptSubmit 意图注入）

```powershell
# UserPromptSubmit hook：识别你"要派给 DSH"的自然说法，并把正确做法直接注入模型上下文。
# PreToolUse 只能看到"模型已经决定调哪个工具"；这个事件拿到的才是你输入框里的原话。
$ErrorActionPreference = 'Stop'
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
try { [Console]::InputEncoding = [System.Text.Encoding]::UTF8 } catch { }

$logDir = Join-Path $PSScriptRoot 'logs'
$logFile = Join-Path $logDir 'dsh-dispatch-hint.log'

function Write-HookLog([string]$Message) {
    try {
        if (-not (Test-Path -LiteralPath $logDir)) { New-Item -ItemType Directory -Path $logDir -Force | Out-Null }
        Add-Content -LiteralPath $logFile -Encoding UTF8 -Value (('{0} {1}' -f (Get-Date -Format 'yyyy-MM-dd HH:mm:ss'), $Message))
    } catch { }
}

$inputJson = [Console]::In.ReadToEnd()
if ([string]::IsNullOrWhiteSpace($inputJson)) { exit 0 }
try { $event = $inputJson | ConvertFrom-Json } catch { exit 0 }

$prompt = [string]$event.prompt
if ([string]::IsNullOrWhiteSpace($prompt)) { exit 0 }

# 触发条件：出现 dsh/DSH，或"派发/派给/交给/指派/让 … deepseek|深度求索"这类说法
$hit = $false
if ($prompt -match '(?i)dsh') { $hit = $true }
elseif ($prompt -match '(派发|派给|交给|指派|让).{0,16}(deepseek|深度求索)') { $hit = $true }
if (-not $hit) { exit 0 }

Write-HookLog ("HINT prompt=" + $prompt.Substring(0, [Math]::Min(160, $prompt.Length)).Replace("`n", " "))

$hint = '用户要求把任务派给 DSH。唯一正确做法：在 exec 里调用 tools.mcp__dsh_crew__dsh_run_worker，参数 { task: <自包含的完整任务>, tier: "flash"|"pro", cwd: <当前工作区绝对路径> }。禁止用 spawn_agent 代替 DSH 派发，也不要自己实现被指派出去的任务。'

$out = [ordered]@{
    hookSpecificOutput = [ordered]@{
        hookEventName      = 'UserPromptSubmit'
        additionalContext  = $hint
    }
}
$out | ConvertTo-Json -Depth 5 -Compress
exit 0
```

### 3.5 关键细节：hook 看到的工具名和你想的不一样（实测）

| 模型侧看到的工具 | hook 里 `tool_name` 的实测值 |
|---|---|
| `exec`（代码模式执行） | `Bash` |
| `spawn_agent`（开子代理） | `collaborationspawn_agent`（命名空间与名字**直接拼接**，没有分隔符） |

所以脚本里用的是**子串匹配** `-match 'spawn_agent'`，才能命中 `collaborationspawn_agent`。
另外：因为 hook 要看到真实工具名，`matcher` 先用 **`.*`（全部）**，由脚本自己判断放行/拦截——这样即使工具改了名也能兜住。

**代价**：catch-all 意味着**每次工具调用都要起一个 `pwsh` 进程**（本机约 100–200ms/次，脚本自身只做 JSON 解析 + 写一行日志）。嫌慢可以把 matcher 收紧成实测真名，但要记住：**Codex 升级后工具名可能变，收紧后需要重新确认**。

### 3.6 验证（必须看日志，不要问模型）

日志位置：`~/.codex/hooks/logs/`

```text
# deny-subagent-dispatch.log —— 每次调用都会记一行 INVOKED，拦截时多一行 BLOCK
2026-09-30 17:43:18 INVOKED event=PreToolUse tool=collaborationspawn_agent mode=strict
2026-09-30 17:43:18 BLOCK mode=strict tool=collaborationspawn_agent input={"task_name":"probe3","message":"...","fork_turns":"none"}
2026-09-30 17:43:27 INVOKED event=PreToolUse tool=Bash mode=strict

# dsh-dispatch-hint.log —— 命中"派给 dsh"这类说法时记录
2026-09-30 17:05:36 HINT prompt=把这件事派发给dsh
```

拦截生效时，Codex 侧会打印：

```text
hook: PreToolUse
ERROR codex_core::tools::router: error=Tool call blocked by PreToolUse hook: 已禁用 Codex 自建子代理：… Tool: collaborationspawn_agent
hook: PreToolUse Blocked
```

**只有日志里出现 `INVOKED` / `BLOCK` / `HINT`，才算钩子真的生效**；模型说"我被拦住了"或"我没被拦"都不算证据。

### 3.7 只想临时关掉 hook

- 把 `deny-subagent-dispatch.ps1` 里的 `$Mode` 改成 `'dispatch-only'`（只拦"像派发给 worker"的）；或
- 从 `hooks.json` 里删掉对应条目（记得之后重新信任剩下的条目）；或
- 在 Codex 设置 → Hooks 里把那条禁用。

## 四、`~/.codex/AGENTS.md`（全局派发规则参考）

hook 之外再放一条提示层规则（双保险）。在 `~/.codex/AGENTS.md` 末尾追加：

```markdown
## DSH 派发

- 需要把任务交给 DSH 执行时，只允许在 `exec` 内调用 `tools.mcp__dsh_crew__dsh_run_worker`（`tier=flash|pro`，`cwd` 传当前工作区的**绝对路径**）。
- 禁止用 `spawn_agent` / `collaboration.*` 代替 DSH 派发；禁止主代理自己实现被指派出去的任务。
- 派发后只反馈工具返回值与真实产物，不臆造执行结果。
- 同一工作区同时只允许一个写者：遇到 cwd 锁拒绝时，等前一个任务结束或换目录，不要加 `allow_concurrent_cwd`。
```

说明：

- 这里写的是 `tools.mcp__dsh_crew__dsh_run_worker` 的**代码模式命名空间写法**，因为该工具不在 Codex 顶层工具列表里。
- 全局 AGENTS.md 只对 Codex 生效（Claude Code 读 `~/.claude/CLAUDE.md`，其他宿主各不相同）；hook 同样是 Codex 专有。跨宿主请各自配置。

## 五、只删不改：角色文件处理

插件安装时会写两个"角色文件"：

```text
C:\Users\<you>\.codex\agents\ds-flash.toml
C:\Users\<you>\.codex\agents\ds-pro.toml
```

它们的目的本来是给宿主一个"原生子代理"入口，但在 Codex 上会带来两个副作用：

1. 名字里带 `flash`/`pro`/worker，和"把活派给 worker"这句话**语义撞车**，模型会优先开子代理；
2. 模板里写死了 `model = "gpt-5.4-mini"`，当前 Codex 版本/账号不支持，一 spawn 就报 `Unknown model`。

**推荐直接删掉**（本教程不用角色路线）：

```powershell
Remove-Item "$env:USERPROFILE\.codex\agents\ds-flash.toml","$env:USERPROFILE\.codex\agents\ds-pro.toml" -Force
```

回滚方式：插件设置页点「安装 / 更新」会重新写入（但上面两个副作用也会一起回来）。
