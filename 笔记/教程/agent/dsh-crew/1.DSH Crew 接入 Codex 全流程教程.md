# DSH Crew 接入 Codex 全流程教程

更新时间：2026-09-30
本机验证版本：`codex-cli 0.159.0`（Codex 桌面版内置）· `@zseven-w/dsh-crew 0.1.0-rc.11` · `@hytime/dsh-thinking-effort 0.3.6` · `Node v24.15.0` · DSH 桌面版

## 适用场景

这篇教程用于把 **DSH（DeepSeek Harness）** 变成 **Codex 的执行后端**：Codex 当指挥，任务派给 DSH 的 agent 真正执行，执行过程在 DSH 里可见。

适合以下需求：

- 不想把重活交给 Codex 自己跑（省 Codex 额度、想用 DSH 里已配好的模型）。
- 想让 Codex 的"子任务"实际落在 DSH 上执行，并能在 DSH 侧看到会话和进度。
- 需要一套**不需要另外申请 API key** 的配置方案（本教程的主路径就是零额外 key）。

不适合：只想在 DSH 内部调度、不接 Codex 的场景（那不需要本文）。

## 先理解架构：两层模型

接入后会有"两个模型"在协作，混淆这两层是本项目最常见的理解障碍：

| 层 | 跑在哪 | 模型由谁决定 | 干什么 |
|---|---|---|---|
| ① 调度员（orchestrator） | **Codex 内部** | Codex 会话模型（或角色文件里的 `model`） | 读需求、写任务简报、调用派发工具 |
| ② worker | **DSH 内部** | 档位绑定：`flash`/`pro` → DSH 的 provider + model | 真正改文件、跑命令、出结果 |

关键结论：

- **"派发给 DSH"这件事本身不需要 Codex 侧指定任何模型**，它只是一次工具调用。
- 只有走"角色（ds-flash / ds-pro）"这条可选路线时，才会去读角色文件里的 `model`（那是调度员的模型，跟 DSH 用哪个模型干活无关）。
- 本教程**不使用角色路线**，直接用主会话派发，链路最短。

## 前置条件检查

| 项 | 要求 | 检查命令 / 位置 |
|---|---|---|
| DSH | 已安装并能正常对话 | 桌面版打开即可 |
| DSH 侧有可用模型路由 | 至少一条已登录/已配 key 的 provider | DSH「设置 → 模型」，绿点表示可用 |
| Codex | 桌面版或 CLI，且能正常跑 | `codex --version` |
| Node | 在 PATH 上（Codex 用它启动 MCP） | `node -v` |
| 端口 | 知道 DSH 实例的端口（下面第 2 步要用） | 桌面版看浏览器地址栏；`dsh web` 默认 3080 |

确认 DSH 的 hub 端点活着：

```powershell
# 把 <port> 换成你 DSH 实例的实际端口，例如桌面版常见是 19387
Invoke-RestMethod "http://127.0.0.1:<port>/_dsh/dsh-crew/ping"
```

期望返回：

```json
{"ok":true,"service":"dsh-crew-hub"}
```

> 返回 `cannot connect` 说明 DSH 没跑，或端口不对。
> 返回 404 说明插件还没装（下一步）。

## 步骤 1：安装 DSH Crew 插件

方式一（推荐）：DSH「设置 → 插件市场」搜索 `@zseven-w/dsh-crew` 安装。

方式二（CLI）：

```bash
dsh plugin --profile <profile> add @zseven-w/dsh-crew@latest
```

`<profile>` 是 DSH 的 profile 名，桌面版通常是 `desktop`。本机 profile 目录：

```text
C:\Users\<you>\.dsh\profiles\desktop\
```

**验证**：DSH 设置里出现「DSH Crew」页；再次访问上面的 `/_dsh/dsh-crew/ping` 返回 `dsh-crew-hub`。

## 步骤 2：配置 Hub 地址（最容易忽略、也最致命的一步）

插件的出厂默认 `hub_url` 是 `http://127.0.0.1:3080`，而 **DSH 桌面版的端口通常不是 3080**。这一项不配对，后面所有派发都会静默回退到 standalone 模式并报缺少 API key。

操作：DSH「设置 → DSH Crew → 运行 → **Hub 地址**」填实际地址，例如：

```text
http://127.0.0.1:19387
```

对应配置文件（`~/.config/dsh-crew/config.json`）里的字段：

```json
"hub_url": "http://127.0.0.1:19387"
```

**验证**：

```powershell
Invoke-RestMethod "http://127.0.0.1:<port>/_dsh/dsh-crew/providers"
```

返回里能看到 `providers` 列表和 `bindings`，说明 hub 与插件、插件与配置都通了。

## 步骤 3：配置档位 → 模型路由（零额外 API key）

### 3.1 为什么必须改

插件出厂把两个档位绑在 **`deepseek-official`** 上，那是"官方 API Key"路由，需要单独提供 `DEEPSEEK_API_KEY`。**本方案不需要这条路由**，要把它换掉。

### 3.2 两条零额外 key 的路线（二选一）

**A 路线（最省事）**：用 DSH 里已登录的账号路由

```json
"flash_provider": "deepseek-account",
"flash_model": "deepseek-flash",
"pro_provider": "deepseek-account",
"pro_model": "deepseek-flash"
```

**B 路线**：用你自己已经在 DSH 配好的第三方路由（示例：字节-火山）

```json
"flash_provider": "huoshan",
"flash_model": "DeepSeek-V4.1-Flash",
"pro_provider": "huoshan",
"pro_model": "DeepSeek-V4.1-Flash"
```

> provider id 与 model id 以你 DSH 里实际为准：打开 DSH「设置 → 模型」点某条 provider 的「编辑」即可看到它的模型 id 列表。
> B 路线请先完成[步骤 4](#步骤-4按需补推理档位)，否则会报 `UNSUPPORTED_REASONING_EFFORT`。

### 3.3 改哪里

**这一项在 DSH Crew 设置页没有输入框**，只能改文件或用工具改（详见[第 4 篇配置项地图](./4.DSH%20Crew%20配置项地图.md)）。

编辑 `C:\Users\<you>\.config\dsh-crew\config.json`，完整示例（可直接对照替换）：

```json
{
  "default_tier": "flash",
  "default_effort": "high",
  "mode": "auto",
  "default_timeout_seconds": 1800,
  "hub_url": "http://127.0.0.1:19387",
  "tier_policy": "auto",
  "escalate_on_failure": false,
  "vision_provider": "off",
  "vision_model": "default",
  "imagegen_provider": "off",
  "custom_providers": [],
  "extra_models": {},
  "flash_provider": "huoshan",
  "flash_model": "DeepSeek-V4.1-Flash",
  "pro_provider": "huoshan",
  "pro_model": "DeepSeek-V4.1-Flash",
  "preset_flash": "default",
  "preset_pro": "default"
}
```

要点说明：

- `tier_policy` 建议 `auto`；填 `flash-only` 会把所有 pro 请求夹成 flash（想用两档就别填这个）。
- `default_effort` 必须落在目标模型支持的档位集合里（见步骤 4）。
- **改完必须重启 Codex 桌面版**：MCP 进程在启动时只读一次这份配置。

### 3.4 验证

```powershell
(Invoke-RestMethod "http://127.0.0.1:<port>/_dsh/dsh-crew/providers").bindings
```

期望 `custom = true`，且 provider/model 就是你填的那对：

```json
{"flash":{"provider":"huoshan","model":"DeepSeek-V4.1-Flash","custom":true}, ...}
```

## 步骤 4：按需补推理档位

判断方法：直接派一个最小任务（见步骤 7 的命令）。如果报：

```text
provider "huoshan" model "DeepSeek-V4.1-Flash" does not support reasoning effort "high"
```

说明这个模型在 DSH 里**没有声明推理档位**，而插件总会带上 `default_effort`，于是被拒。两种情况：

- **A 路线（deepseek-account 等 DSH 内置目录里的模型）**：一般自带档位，通常不用管。
- **B 路线（自己在 profile 里手写声明的 llm-pi-ai 模型）**：需要装补档位插件。

![reasoning effort 报错](./image/1.dsh-crew-接入流程/4.reasoning%20effort%20报错.png)

安装补档位插件：

```bash
dsh plugin --profile <profile> add @hytime/dsh-thinking-effort
```

装完打开 DSH「设置 → **第三方模型思考强度档位**（Model capabilities and effort）」：

1. 确认目标模型已经有档位（插件会自动给"用户层声明且未声明档位"的模型补默认档位）。
2. 没有的话用 **Quick settings** 的 generic preset 应用到全部模型，或展开到该模型手动勾选。
3. 记下该模型实际支持的档位集合——**`default_effort` 必须是其中之一**。

本机实例（火山 `DeepSeek-V4.1-Flash`）实测档位集合是 `minimal / high / xhigh / max`，**没有 `off`**：
所以 `default_effort` 必须保持 `high` 或 `max`，设成 `off` 同样会报不支持。

> 经验：装完这个插件后，profile 的 `cordis.patch.yml` 会被自动写入 `reasoningEfforts`，可以 `git diff` 或直接看文件确认。
> 但**不是所有模型都会被自动补上**（本机 `GLM-5.3-Flash` 就没补上，派发仍然失败）——用到哪个模型就确认哪个。

## 步骤 5：在 Codex 侧注册 dsh-crew MCP

**为什么需要这一步**：插件的 Codex 集成只会把 MCP 挂进两个"角色文件"（`~/.codex/agents/ds-flash.toml`、`ds-pro.toml`），**主会话拿不到这些工具**。所以要让主会话能派发，必须把 MCP 注册到 Codex 的主配置里。

### 方式一：界面（推荐）

Codex 桌面版「设置 → MCP → **Add server**」，在 "Connect to a custom MCP" 表单里填：

| 字段 | 值 |
|---|---|
| Name | `dsh-crew` |
| 类型 | `stdio`（标准输入输出） |
| Command to launch | `node` |
| Arguments | `C:\Users\<you>\.dsh\profiles\<profile>\node_modules\@zseven-w\dsh-crew\src\server.mjs` |
| Working directory | 留空 |

保存后 Codex 的 MCP 列表里会出现 `dsh-crew`，状态为已启用：

![Codex MCP 已启用](./image/1.dsh-crew-接入流程/2.Codex%20MCP%20已启用.png)

### 方式二：直接写配置文件

编辑 `C:\Users\<you>\.codex\config.toml`，把下面这段追加到文件**末尾**（它是独立 TOML 表，追加安全）：

```toml
[mcp_servers.dsh-crew]
command = "node"
args = ["C:\\Users\\<you>\\.dsh\\profiles\\<profile>\\node_modules\\@zseven-w\\dsh-crew\\src\\server.mjs"]
default_tools_approval_mode = "approve"
tool_timeout_sec = 3600
```

- 路径里的反斜杠必须写成 `\\`（TOML 字符串转义），否则 Codex 会报 `TOML parse error` 并**静默忽略整个角色/服务器定义**。
- `default_tools_approval_mode = "approve"` 是插件文档点名的必需项，少了工具调用可能被自动取消。
- `command = "node"` 依赖 Node 在 PATH 上；不确定就写 `node.exe` 的绝对路径。

也可以用官方 CLI 注册（等价，但上面两个附加字段仍需手工补）：

```bash
codex mcp add dsh-crew -- node "C:\Users\<you>\.dsh\profiles\<profile>\node_modules\@zseven-w\dsh-crew\src\server.mjs"
```

### 验证

```bash
codex mcp list
```

应出现 `dsh-crew ... enabled`。然后**重启 Codex 桌面版**（让每个新会话都带上这套工具）。

## 步骤 6：可选加固（建议做）

这两步都是为了"让 Codex 别用自己的子代理顶替 DSH"，详见[第 4 篇](./4.DSH%20Crew%20配置项地图.md)：

1. **删掉插件的两个角色文件**（去掉歧义源）：

```powershell
Remove-Item "$env:USERPROFILE\.codex\agents\ds-flash.toml","$env:USERPROFILE\.codex\agents\ds-pro.toml" -Force
```

> 注意：插件设置页点「安装 / 更新」会把它们写回来。

2. **加 hook + 全局 AGENTS 规则**：hook 参考实现与完整内容见[第 4 篇配置项地图](./4.DSH%20Crew%20配置项地图.md)（本机已验证能拦下子代理）。

## 步骤 7：验收（第一次成功派发）

在 Codex 里发一句（点名工具路径最稳）：

```text
用 exec 调用 tools.mcp__dsh_crew__dsh_run_worker，参数
{"task":"只回复两个字：收到。不要调用任何工具，不要读写任何文件。","tier":"flash","cwd":"<你的工作区绝对路径>"}
把工具返回值原样贴给我。
```

三条证据必须同时成立：

1. Codex 侧出现 `mcp: dsh-crew/dsh_run_worker started` → `completed`；
2. 返回值里有 worker 的回答（本例是 `收到`）和 token 用量；
3. hub 里能查到这条 job：

```powershell
(Invoke-RestMethod "http://127.0.0.1:<port>/_dsh/dsh-crew/jobs").jobs |
  Select-Object id,tier,status,provider,model,cwd,startedAt
```

看到 `status = done`、`provider/model` 与你配置的一致，就算接入完成。

### 关于"派发命令怎么写"

`tools.mcp__dsh_crew__dsh_run_worker` 这个名字**不在 Codex 的顶层工具列表里**，它挂在 `exec` 的代码模式命名空间下（可以用 `Object.keys(tools)` 自查）。所以：

- 自然语言说"派给 DSH"**不可靠**——模型更可能用它的自建子代理（`spawn_agent`），见[排障手册症状1](./2.DSH%20Crew%20派发链路与排障手册.md#症状1-codex-自己开了个子代理)。
- 稳妥做法是**点名工具路径 + `cwd` 绝对路径**；或者按第 4 篇配好 hook 与 AGENTS 规则，让系统帮你兜住。

## 常见失败速查

| 现象 | 先看 |
|---|---|
| 报 `no API key for provider route "deepseek-official"` | 步骤 3（档位还绑在默认路由上） |
| 报 `does not support reasoning effort` | 步骤 4（档位不匹配/未声明） |
| 报 `cwd must be an absolute path` | 派发时 `cwd` 传了相对路径 |
| 报 `workspace ... is already held by a running worker` | 同一工作区已有 worker 在跑；等它结束或换目录 |
| Codex 自己开了子代理，DSH 没收到任务 | [排障手册](./2.DSH%20Crew%20派发链路与排障手册.md) |
| MCP 列表里没有 dsh-crew | 步骤 5（注册 + 重启 Codex） |
